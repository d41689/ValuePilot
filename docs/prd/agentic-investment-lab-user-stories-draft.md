> 版本：0.2 Draft · 2026-09-22（用户确认第三方复审通过）
>
> 状态：产品提案，复审通过；不是已获批的实施规范或交易授权。
>
> 目标读者：产品负责人、投资决策者、架构与安全评审者、后续实现及验收人员。
>
> 本次交付：明确用户故事、验收条件、分期和待决事项；不实现功能、不连接账户。

## 1. 产品定义与关键决定

**让长期投资者在 ValuePilot 内管理一个可审计的投资实验室：多个研究 Agent 提出
可证伪的判断，在明确授权和确定性风险约束下形成模拟组合，再用后续事实检验判断，
通过可比较的实验改进 Agent。真实资金是后续可选阶段。**

核心闭环：

```text
可信证据 → 独立研究与反证 → 决策卡与可检验预测 → 组合提案
    → 授权检查 + 确定性风险检查 → 模拟执行 → 结果核验与复盘
    → 候选改进 → 新旧版本对照 → 人类批准启用
```

建议本轮评审采用以下产品方向：

1. **产品合并进 ValuePilot，执行权限独立。** 沿用公司身份、获准事实、用户研究与
   投资记忆；Lab 不建立第二套财务事实、用户估值或研究真相。
2. **先完成一个小而完整的 paper 闭环。** 第一版可配置资产仅为股票多头与现金；
   ETF 可作为业绩比较基准，但不进入可交易清单。不以接通某家券商作为 MVP 完成条件。
3. **Agent 可以自主开展被授权的模拟实验。** 人类不必逐笔确认 paper 行为，
   但必须先批准实验范围；模拟判断永远不自动成为用户正式投资观点。
4. **保留人类对真实资金的决定权。** 首次真实账户试点采用逐笔批准；更高自主度
   另行评审，不由 paper 成绩、模型置信度或用户沉默自动解锁。
5. **学习的目标是可验证的决策改善。** 同时检查证据使用、关键经营预测、概率质量、
   资本损失风险、成本和长期结果，不把短期 P&L 合成为唯一奖励。

“巴菲特／芒格式”在本文中体现为企业所有者视角、能力圈、经济实质、安全边际、
机会成本、耐心及主动反证。Agent 的名字或模仿大师的语气不构成质量证明。
企业长期经济进展与每股价值是重要观察对象，短期价格只是其中一种观察；这一取向
与 Berkshire 的所有者原则一致。[Berkshire Owner’s Manual](https://www.berkshirehathaway.com/owners.html)

## 2. 与现有 ValuePilot 合同的关系

### 2.1 必须显式处理的边界变化

[研究决策架构 §9](../architecture/research-decision-support.md) 目前明确禁止
broker order submission、订单路由／修改／撤销／执行及自动交易；
[权威 PRD §G](value-pilot-prd-v0.1.md) 将 portfolio 定义为人工持仓日志。
**本提案申请新增 Lab 产品域；不把交易能力解释为现有研究模块已授权的延伸。**

| 现有边界 | 本提案处理方式 | 实施前要求 |
| --- | --- | --- |
| AI 只能提出，正式研究由用户接受 | 保持；自主 paper 判断归属于实验，不晋升为用户观点 | 定义 Lab proposal 与 accepted research 的引用和展示合同 |
| 用户估值只能走 canonical publication | 保持；Agent 情景值为实验假设，不是用户 MOS 的新来源 | 涉及用户接受时继续走唯一发布事务 |
| Portfolio 是人工日志，无 broker 准确性承诺 | 人工日志、模拟账本、真实券商观察分别标识 | 获批新账本／对账合同，不静默升级现有 portfolio |
| 当前无交易通道 | 提议先引入 paper，真实执行单独放行 | 修改权威 PRD、架构边界及路线图；live 再完成安全与适用法律评审 |
| 私有研究不用于跨用户训练 | 保持；默认学习仅限拥有者的实验 | 外部模型处理与训练用途分别取得必要授权 |

本文中的对象名称、阶段和状态是产品语言，不直接规定数据库表、API、服务拆分或
新的 `metric_key`。正式实现必须先将获批行为纳入各自权威文件。

### 2.2 复用与依赖

- 复用现有股票身份、来源权限、canonical financial facts、研究 case/revision、
  canonical valuation 服务、人工持仓日志及 Research Inbox 的既有合同。
- 与工作区中的投资记忆与论点监控草案（`docs/prd/investment-memory-monitoring-prd-draft.md`）共享研究历史、
  来源变化和复盘入口的方向；该文也是草案，不能据此宣称相应功能已经实现。
  该背景草案尚未进入本提交的 main 基线，不随本提案提交；此处是后续整合依赖。
- 能力圈、经营质量、正常化所有者收益和可靠来源是上游依赖。覆盖不足时允许导入
  有来源的人工研究假设，或缩小实验股票池；不得让 Agent 编造事实以完成交易链。
- Lab 的订单及成交记录不写入 `metric_facts` 充当企业财务事实；历史实验引用稳定
  fact/source 版本，不能用今天的 `is_current` 查询假装还原过去。

## 3. 用户、权限与价值

### 3.1 角色

| 角色 | 用户真正需要的能力 | 不包含的权力 |
| --- | --- | --- |
| 投资者／实验拥有者 | 设定投资章程、运行实验、接受或拒绝研究、复盘并决定是否采用改进 | 不因开启 paper 而授权 live |
| 组合负责人 | 在候选、现有持仓和现金之间评估机会成本 | 不以研究提案绕过风险限制 |
| 研究复核者 | 经拥有者授权，检查证据、反证和预测核验 | 不默认读取他人私有研究或下单 |
| 系统运营者 | 看运行失败、延迟、成本和账户连接健康 | 不默认读取私人 thesis、凭证或投资组合明细 |

以上是职责视角；MVP 可由同一用户承担投资者与组合负责人，不要求先实现团队 RBAC。
下文角色 Agent 是产品内职责，不代表每种职责都需要独立模型、进程或微服务。

### 3.2 北极星与可观察价值

| ValuePilot 投资工作 | Lab 提供的帮助 | 验收中可观察的结果 |
| --- | --- | --- |
| 能力圈 | 明确未知、拒绝无法理解的标的 | 看得见“不投／暂缓”的理由及补证条件 |
| 企业质量 | 对护城河、管理层、资本配置和再投资回报做证据化判断 | 关键主张可追溯，反方可挑战 |
| 正常化所有者收益 | 区分事实、调整和估计 | 现金流与每股经济性假设可解释 |
| 安全边际 | 用情景和敏感性约束配置提案 | 价格／估值／未知变化有不同处理 |
| 决策前反证 | 记录最强反方、kill criteria 和不行动选项 | 共识不能消除未决反证 |
| 论点监控与复盘 | 将事前预测与事后观察对应 | 无法事后改写预测或挑选成功案例 |

## 4. 分期和非目标

| 阶段 | 用户可获得的结果 | 边界与退出证据 |
| --- | --- | --- |
| S0 合同与实验准备 | 确认实验章程、数据范围、权限及评估协议 | 下述 D1–D5 中 S1 所需决定获批，相关权威合同更新，数据能力矩阵可检查 |
| S1 Paper MVP | 一组 Agent 完成研究、模拟配置、风险检查、模拟账本及首次复盘 | §10 端到端场景通过；没有真实账户凭证或真实下单路径 |
| S2 可验证学习 | 到期预测核验、概率评分、对照实验和候选版本评估 | 完整报告胜败及未决样本；能够判定“尚无改善证据” |
| S3 小额真实试点 | 隔离资金范围、逐笔人工批准、执行和对账 | D6–D7 获批；候选版本满足下述准入规则；权限与故障演练通过；金额由用户单独确定 |
| S4 后续研究 | 更高自主度、更多策略或资产类别 | 另立验收与授权，不在 S1–S3 默认承诺内 |

S1 提议的最小实验：一个用户、一个 paper 账户、一种计价币种 USD、一个有限股票池，
仅配置股票多头与现金，采用长期低换手章程；至少有主要研究、独立反证、组合提案三种职责。
股票池与资金规模在创建实验时填写，不预置“适合用户”的实盘仓位或金额。

ETF／指数基准只用于相同口径的结果比较，不产生可执行配置、持仓或订单。基金交易需
另立适用研究与决策卡合同，留到 S4 评审；S2/S3 不因阶段推进自动扩大资产范围。

**S3 候选版本准入：** 必须是实验事前指定的初始基线，或按 AIL-25 晋升的版本；
两者都必须以实际候选版本完成预注册的前瞻 shadow/paper 过程与控制验证，并满足
事前确定的覆盖、观察期和风险门槛。仅有技术演练或受污染历史成绩不够。
“尚无改善证据”的 challenger 继续留在模拟阶段，不能改名为基线绕过准入；若旧基线
自身没有合格前瞻证据，整个 S3 仍被阻断。基线的长期投资能力可标为未知，用户可以
在明确知情下另行批准有金额上限、逐笔确认的执行试点，但不能将其宣传为已验证 alpha。
完成 S2 评估不等于通过上述准入，也不自动授权任何真实交易。

Shadow 是 S1 的可选运行方式：保存提案和观察，不记模拟成交。
Paper 则有明确的模拟成交及账本。两者不能混为同一种收益记录。

S1 建议按三个可演示切片推进：先跑通“既有研究 → 多视角挑战 → 卡片”，再接入
“配置 → 风控 → 模拟账本”，最后完成“检查点 → 人工复盘 → 可追溯导出”。
研究故事可先使用用户已确认、带来源的结构化输入，不要求同时建设全自动企业研究、
新数据供应商、复杂估值编辑器或统计归因引擎；缺少必要输入的企业不进入可交易实验池。
只有三个切片连通才称为 S1 闭环，某个页面或 broker adapter 单独完成不算 MVP 完成。

**本轮不包含：** 高频交易、市场择时机器人、期货／保证金／卖空／期权／加密资产、
自动充值转账、税务申报、跨用户基金或跟单市场、无监督实盘强化学习，以及仅为
架构完整而新增的微服务平台。指数期货复制 ETF 的原会话主题不是本次 MVP 的依赖。

## 6. 详细 User Stories

### Epic A — 先定义实验，再让 Agent 行动

#### AIL-01｜建立投资章程与实验协议〔S1〕

**作为长期投资者，我希望在运行前说明 Agent 在什么范围内追求什么结果，
以便实验遵守我的能力圈、资金约束和投资期限。**

验收条件：

1. 必填实验拥有者、paper/shadow 模式、币种、初始模拟资金、允许标的、禁止行为、
   研究／复核频率、运行预算、风险限制及授权期限。缺少必需项不能启动。
2. 记录投资期限、能力圈、可承受的实验损失预算及比较基准；明确等待和持有现金
   可以是有效决定。风险限制数值由用户确认，不把会话中的 5%／10% 当投资定律。
3. 预先保存评价口径、预计观察期与版本比较方法。后续修改生成新协议版本及生效时间，
   不重新解释旧实验成绩。运行前由用户确认适用于本股票池／研究方法的必需覆盖项、
   决策关键输入及其绑定的动作；可采用获批版本化规则，但 Agent 无权增删或降级要求。
   修改只对按新版本启动的运行生效，旧运行不因补改规则而变为通过。
4. 给定只启用了 paper，任何 live 请求都被拒绝；投资章程不是券商授权。

#### AIL-02｜从已有研究启动实验〔S1〕

**作为研究者，我希望从现有 case、Watchlist 或手动选定公司启动 Lab，
以便实验承接既有知识，又能辨认哪些判断是实验新产生的。**

验收条件：

1. 绑定拥有者、准确公司／上市身份、研究周期和固定 revision；保存发现来源。
2. 显示继承的用户判断、当前事实、Lab 假设三者的区别；实验不修改源 revision。
3. 缺少研究或来源时列出具体缺口；可进入补证或观察流程，不能伪装成完成研究。
4. 其他用户的私有 case、文档和历史教训不进入上下文；同一股票身份不构成访问权限。

#### AIL-03｜配置职责并控制运行〔S1〕

**作为实验拥有者，我希望知道谁负责研究、谁负责反证、谁提出组合，
并能控制运行时间和费用，以便检验各职责是否值得保留。**

验收条件：

1. MVP 提供主要研究、独立反证、组合提案职责；质量、增长、估值、Quant、Macro
   可作为后续可选视角，不要求先运行六个独立 Agent。
2. 每次运行保存职责、模型／提示／工具／策略版本、获准输入清单、起止时间、费用与状态。
3. 必需反证任务失败、超时或预算耗尽时，运行标为未完成；不当作已通过委员会。
4. 用户可暂停后续调度；重试可追踪且不会重复产生同一模拟订单。研究角色没有执行工具，
   任意资料或 Agent 文本均不能修改授权、预算或风险策略。

### Epic B — 像企业所有者一样研究，并主动寻找错误

#### AIL-04｜固定当时可用的证据〔S1〕

**作为投资者，我希望看到本次判断实际使用的证据和时间边界，
以便发现遗漏、冲突和后见之明。**

验收条件：

1. 每个关键主张关联可访问来源、定位、经济期间、币种／单位、来源版本、发布时间、
   系统获知及处理时间；未知时间明确未知，不补填成“当时已知”。
2. 事实、管理层主张、用户判断、Agent 推断和计算输出分别标识；Agent 旧回答不作为事实来源。
3. 按 AIL-01.3 固定的覆盖要求确定阻断，而非由本次模型判断“是否关键”。必需项或
   决策关键输入 missing/stale/conflicting/blocked/unknown 时显示原因，阻止其绑定的
   可执行配置提案；不引用、改称非关键或提高置信度都不能解除阻断。允许研究草稿、
   补证及观察；不使用未披露的替代数值。已声明允许的估计区间必须标明假设，不能冒充事实。
4. 更新或纠错保留旧证据引用和新版本关系。回放按当时可用版本进行，缺口显示为部分重建；
   不把今日 current facts 当作历史知识。

#### AIL-05｜判定能力圈与企业质量〔S1〕

**作为价值投资者，我希望 Agent 解释企业如何赚钱、优势为什么能持续以及我可能不懂什么，
以便避免在无法理解的企业上下注。**

验收条件：

1. 输出客户与收入来源、单位经济性、竞争优势、资本密集度、再投资空间、管理层激励、
   资本配置及资产负债表脆弱点；无证据项保持未知。
2. 每项关键质量判断至少展示支持证据、可替代解释和可能改变判断的观察条件。
3. 可以明确“超出能力圈／暂不判断”；这类结论不因妨碍交易数量而被降分。
4. 会计完整性、融资依赖、客户集中等风险单列，不被综合质量分的均值掩盖。

#### AIL-06｜解释正常化所有者收益〔S1〕

**作为投资者，我希望从报告财务走到可解释的正常化经济收益，
以便估值不依赖漂亮但无法兑现的利润。**

验收条件：

1. 将已知净利润／现金流与营运资本、资本开支、SBC／稀释、并购、一次性项目、周期影响
   对照；区分报告事实、确定性计算和研究估计。
2. 维持性与增长性资本开支无法可靠分拆时展示区间或未知，不自动把全部自由现金流当所有者收益。
3. 每个调整有理由、来源和版本；防止同一成本在现金流与股份稀释中重复扣减。
4. 行业方法不适用时标为不适用并阻断依赖的估值，不用统一工业企业模板硬算金融企业。

#### AIL-07｜建立情景估值与机会条件〔S1〕

**作为投资者，我希望看到估值范围及最影响结果的假设，
以便判断当前价格提供的余地是否足以覆盖不确定性。**

验收条件：

1. Bear/base/bull 或用户选定情景明确经营假设、每股口径、债务／现金处理、估值方法、
   期限、币种及价格时间；展示关键变量敏感性。
2. 情景权重若提供必须非负且合计为 1；这是实验假设，不能标成已校准的事实概率。
3. MOS 的用户标签仍仅来自当前合格的 canonical 用户估值；Agent 候选值只显示实验比较。
   价格缺失、过期或币种不符时不输出伪精确比较。
4. Expected IRR 为可选扩展：只有现金流、期间、费用／分红及终值口径完整并有确定性
   计算合同才展示；否则显示不可用。不能简单将情景 IRR 加权后当组合预期复利。

#### AIL-08｜先独立研究，再比较分歧〔S1〕

**作为决策者，我希望反方真正挑战投资理由，
以便多个 Agent 不只是重复同一种乐观叙事。**

验收条件：

1. 主要研究与反方先分别提交初步判断，再相互评议；保留前后版本及共用来源。
2. 反方必须给出最强替代解释、损失路径、关键未知、需补证内容及可证伪条件，不能只写泛泛风险。
3. 委员会汇总共识、分歧和未解决问题；多个同源回答不计为多份独立证据，不能用多数票抹去反证。
4. 重大未决问题可以导致补证、等待或拒绝；任何 Agent 都不能以“大师风格”或置信度免除证据要求。

### Epic C — 先留下可反驳的记录，再行动

#### AIL-09｜在行动前冻结 Decision Card〔S1〕

**作为实验拥有者，我希望每一次行动或不行动都有一张事前决策卡，
以便未来知道 Agent 当时究竟相信什么。**

验收条件：

1. 决策卡包含 §7 的最低内容，并在发出模拟订单意图之前保存；补写理由不能冒充事前记录。
2. 支持买入、加仓、维持、减仓、退出、观察、放弃和证据不足；动作属于 Lab，不映射为
   现有 case 的 `watch/own/pass` 自动变化。
3. 卡片版本不可静默覆盖；观点、价格条件、输入或风险策略变化产生新版本，原版本仍可复盘。
4. 交易提案无有效卡片、证据链或授权时被拒绝；不交易也有复核日期／事件，避免永久遗忘。

#### AIL-10｜把判断转换成可结算预测〔S1〕

**作为希望改善判断的投资者，我希望事前定义“什么发生才算预测成立”，
以便评分不依赖事后选择口径。**

验收条件：

1. 每条预测有对象、可观测事件或数值、经济期间、目标日期、解析来源、定义／单位、
   初值、概率或区间、核验规则及数据更正处理方式。S2 评价还须绑定事前登记的预测
   机会及评分单位；应预测但未创建的项目保留遗漏原因，不能改写为普通叙述后从分母消失。
2. 二元预测的概率绑定明确事件；“我对买入有 72% 信心”不能直接当作可结算概率。
3. 长期 thesis 可拆为中期经营检查点；季度数据仅验证对应检查点，不提前结算五年预测。
4. 没有可信实际值、尚未到期、定义不一致或来源争议时标为未决／不可核验，不能填 0 或计为失败。

#### AIL-11｜区分实验判断与我的正式决定〔S1〕

**作为用户，我希望采纳、编辑或拒绝 Agent 的研究，而不是被实验自动代表，
以便正式投资记忆始终体现我的判断。**

验收条件：

1. 自主 paper 决策清晰标为“Agent 实验判断”；用户批准启动实验不等于接受其每条 thesis。
2. 正式接受需明确操作，记录操作者、原 proposal、用户编辑、expected head 和新 revision；
   过时 head 不可覆盖新判断。
3. 涉及估值发布或清空时继续使用现有 canonical 事务和 monitoring 规则，不新增写入捷径。
4. 接受研究、批准组合、批准真实订单是不同动作；页面访问、通知已读和沉默均不构成其中任何授权。

### Epic D — 组合决定要面对机会成本与生存约束

#### AIL-12｜在现有持仓、候选和现金之间配置〔S1〕

**作为组合负责人，我希望比较持有、增加新机会和继续等待，
以便资金流向我理解且条件更有利的选择。**

验收条件：

1. 提案展示当前及目标数量／权重、现金、增减理由、拟使用资金及关联决策卡；
   解释为何优于维持现状和等待，不强制满仓。
2. 多头股票加现金目标权重合计为 100%，计算基于同一有效账户快照；
   交易成本与预留资金明确，不能只比较静态百分比。ETF 基准不能被转成订单，
   允许标的必须有适用且通过 AIL-05–10 的研究／决策卡链。
3. 展示行业、共同客户／经济驱动、融资和业务失败情景的集中暴露；Beta／波动是辅助信息，
   不能代替永久资本损失分析。
4. 拒绝靠机械等权或统一低仓位上限宣称“价值投资最优”。集中度上限是实验章程约束，
   修改必须由用户完成并留下版本。

#### AIL-13｜执行前通过确定性 Risk Engine〔S1〕

**作为资金负责人，我希望任何提案都接受不能被 LLM 说服或绕开的限制，
以便一次错误推理不会变成无边界敞口。**

验收条件：

1. 检查模式／账户白名单、标的与动作、可用现金及结算限制、当前及在途敞口、
   单笔／单股／行业限制、成交额预算、价格有效性和授权有效期。
2. 同时到达的提案也不能重复使用同一现金或额度；风险校验覆盖成交后及未成交订单的最坏允许敞口。
3. 输出允许、拒绝或等待补证，以及触发规则、输入快照、计算结果、策略版本和时间；
   缺少必需输入时拒绝依赖该输入的订单，不能默认放行。
4. LLM、prompt、来源文本都不能改规则。风控不偷偷缩量／换标的；如需调整，产生新提案重新验证。

#### AIL-14｜分开处理论点受损与价格回撤〔S1〕

**作为长期投资者，我希望真正的企业风险得到优先复核，
同时把资金安全限制与投资结论分开。**

验收条件：

1. 盈利能力、偿债／再融资、会计诚信、管理层或资本配置反证关联原 thesis 和 evidence，
   并显示“待人工判断”或已定义规则的触发结果。
2. 股价下跌可提示复核，但不自动宣称永久损失；自然语言 kill criteria 不由一次 LLM 判词自动裁定。
3. 如章程设置回撤或损失预算熔断，触发后暂停增加风险并生成复核事项；不默认自动清仓。
4. 卖出／减仓仍需自身理由、授权与执行检查；恢复实验必须记录复核及批准，不能等价格反弹自行恢复。

#### AIL-15｜一键暂停并看清仍在途的风险〔S1〕

**作为实验拥有者，我希望随时停止新的行动，
以便处理异常时知道哪些风险已经停止、哪些仍需处理。**

验收条件：

1. 暂停后不接受新的下单动作；发单入口再次检查暂停状态，已排队旧提案不可越过暂停。
2. 显示所有在途／状态未知订单；撤单请求、撤单确认、已成交分别显示，暂停不等于全部撤单成功。
3. 单一账户的执行并发受协调，同一意图重复投递不能变成两笔交易；“单一 Execution”
   指唯一受控权限入口，不要求整个平台只有一个工作进程。
4. 恢复必须由用户显式发起，先刷新账本和风险状态；过期授权或旧批准不能被复用。

### Epic E — 用诚实的模拟和观察跑通闭环

#### AIL-16｜获得可解释的 paper 成交〔S1〕

**作为实验拥有者，我希望模拟成交遵循事前公开的规则，
以便收益不是由不可能成交的价格制造出来的。**

验收条件：

1. 保存模拟器版本、行情来源／可用时间、交易时段、支持订单类型、手续费和滑点规则；
   页面与导出始终标为模拟，不能显示为券商真实成交。
2. 使用日终数据决策时，最早使用决定之后的下一可交易时点模拟；不能看完当日收盘再按
   同一收盘价成交。数据粒度无法证明的盘中成交不得补造。
3. 规则覆盖不成交、部分成交、缺少报价、停牌及费用；只有日线且无法支持细粒度限价／
   流动性假设时，缩小支持订单范围并明确限制。
4. 每笔成交关联原意图、有效授权和风控结果；重复回放不重复记账。更换模拟规则开新版本，
   不追溯美化已公布的结果。

#### AIL-17｜查看自洽且独立的模拟账本〔S1〕

**作为投资者，我希望知道现金、持仓、在途订单和损益为何变化，
以便分清投资判断问题与记录错误。**

验收条件：

1. 数量、现金、费用、成交及分红／拆股等事件能逐项核对；用确定性计算生成余额与估值。
2. 新增／提取模拟资金记录为外部现金流，不当作收益；重置账户建立新实验，不删除失败历史。
3. 公司行动或价格数据缺失时，相应估值／收益标为不完整并暂停依赖它的新配置；不能忽略拆股、
   退市或分红后仍显示完整业绩。只对具有支持数据的范围声称结果可用。
4. 人工持仓日志、paper 账本与后续 live 观察分别标识；模拟成交不自动把用户标记为真实持有。

#### AIL-18｜依据论点和预测安排复核〔S1〕

**作为长期投资者，我希望在预测到期、关键证据改变或反证出现时复核，
以便监控服务于决策，而非不断催促交易。**

验收条件：

1. 每张活跃卡片有日期／事件复核条件，关联 thesis、预测及预定义来源；同一事件不重复轰炸。
2. 复核展示原预测、后来观察、来源差异、可比性和未解决问题；来源覆盖不足不能报“论点未变”。
3. 用户或 Agent 可以提出维持、补证或修订，但正式用户 revision 仍需显式接受；
   监控事件不直接下单，任何新模拟交易重新经过决策卡、授权和风险链。
4. 与投资记忆／监控模块共用获批的引用与复核入口，不另造一套自动接受研究的路径。

#### AIL-19｜记录第一次可行动的复盘〔S1〕

**作为投资者，我希望在每个检查点分辨哪里判断错、哪里只是结果尚未显现，
以便下一次研究有具体改进。**

验收条件：

1. 并列当时卡片、当时证据、后续事实和模拟结果，不只展示盈亏排行榜。
2. 支持“好过程／坏结果”“坏过程／好结果”“证据不足”以及尚未成熟；
   这些是有解释的复核标签，不是模型自动证明的客观真相。
3. 错误区分数据／口径、经营预测、估值假设、组合配置、执行和流程；允许多因及无法确定。
4. 保存待验证教训、适用范围、反例、拟改变行为及关联来源；S1 允许人工标注，
   不承诺已经完成统计学习或自动提高收益。

### Epic F — 证明 Agent 改善，而不奖励幸运

#### AIL-20｜公平比较收益、风险与机会成本〔S2〕

**作为实验评估者，我希望把 Agent 与简单替代方案放在相同条件下比较，
以便判断新增复杂度是否有价值。**

验收条件：

1. 实验开始前确定主基准和现金／简单单 Agent 等对照，固定同一币种、观察期、现金流、
   分红和成本口径；基准来源不可用时标明无法比较。
2. 同时报告绝对／相对回报、现金占比、集中暴露、换手、费用和回撤，保留不交易及失败实验。
   无动作不自动扣分，也不因持有现金少亏就自动被认定更优秀。
3. 时间加权回报用于策略比较；若展示资金加权回报，单列口径及现金流，不能混用。
   小于一年不得把年化数字作为主要证据。
4. 超过基准的收益称“基准相对收益”，不能直接叫风险调整 alpha；税后收益没有获批税务模型
   及完整输入时不展示为真实结果，税务情景只作明确假设分析。

#### AIL-21｜按事前规则核验预测与概率〔S2〕

**作为实验拥有者，我希望知道 Agent 的 70% 是否有相应可信度，
以便识别过度自信并改善预测。**

验收条件：

1. 按 AIL-10 固定的目标、来源和规则生成 resolution；有争议时进入人工复核。
   更正产生新 resolution 并保留原评分版本，不能静默改结果。
2. 对可结算二元事件计算 Brier Score：`BS = Σ(p - o)² / N`，其中 `o` 为 0 或 1，
   分数越低越好；同时报告事件基准率、简单预测基线和可靠性分箱。此式用于等权评分单位；
   晋升主评分按 §8.3 事前固定的底层事件分组、组内汇总和组间权重计算并披露口径，
   不把原始预测条目数直接当作评分权重或独立样本数。
3. 数值预测按预注册口径看偏差／误差，区间预测看覆盖及宽度；不把不同期限、事件类型、
   Agent 版本混成一个“准确率”。Brier 反映整体概率质量，不单独等同于校准。
4. 显示符合资格的完整预测机会数、已创建数、遗漏／弃权数、按预注册规则排除数、
   已结算数、未到期数、无法核验数及各必需类别的覆盖情况。状态明确定义并可核对，
   不能只报已创建或已结算条目的成功分数。同一企业／期间相关预测按 §8.3 处理；
   少样本不发布“已校准”结论，五年预测须等到相应核验时点。

#### AIL-22｜解释结果来源并保留归因限制〔S2〕

**作为组合负责人，我希望知道表现与哪些经营变化、市场暴露和执行成本相关，
以便不把牛市误当选股能力，也不把短期下跌等同于 thesis 错误。**

验收条件：

1. 分开呈现会计上可核对的现金流／成本、经营预测差异、估值变化，以及模型估计的市场／因子暴露。
2. 每项归因有方法、输入、期间、版本与残差；相关性分析标为解释模型，不声称发现因果。
3. 没有获准因子数据或样本不足时，显示无法完成该归因；不把市场、行业、风格等重叠成分
   任意相加凑成总回报，不用简单相减就宣称获得 alpha。
4. “如果当时等待／买基准／维持原仓”只有在事前固定替代规则下才可比较，并标为模拟反事实，
   不允许事后挑最低买点。

#### AIL-23｜在下次研究中使用经复核的教训〔S2〕

**作为投资者，我希望 Agent 记住重复错误和适用条件，
以便下次能提出更好的问题而不机械照搬旧结论。**

验收条件：

1. Lesson 关联原决策、预测、实际证据、复核人及适用范围；Agent 自生成总结先标为候选。
2. 新研究显示引用了哪些教训、为什么适用及不适用的条件；用户可纠正或废止，旧版本仍可追溯。
3. 往期投资意见不能变成当前企业事实；来源失效或权限撤销按既有保留与可见性合同处理。
4. 教训调用不修改风险限制、正式 thesis 或模型版本；私有教训不进入其他用户上下文或
   平台训练集，除非以后另获明确许可。

#### AIL-24｜用对照实验评估改进〔S2〕

**作为实验拥有者，我希望比较旧版与新版 Agent，
以便每次提示、记忆或模型调整都有证据，而不是凭一次好结果升级。**

验收条件：

1. 预注册要检验的改变，例如补充经营反证、修改检索规则、校准概率；保存不可变版本。
   默认先改流程／提示／检索与规则，不要求训练模型权重或在线 RL。
2. Champion 与 challenger 使用匹配的输入截止、股票范围、资金、风险预算和模拟规则；
   评价前按 §8.3 固定完整机会队列、必需类别、评分单位和权重。保存成本及耗时，
   并设简单单 Agent 对照来检验多 Agent 的增量价值；各版本不能自行挑选不同事件参评。
3. 按时间区分开发、验证和未参与调参的检验窗口；记录所有候选尝试和失败结果，
   不反复调到验证集胜出后声称样本外成功。队列内重置、改名、终止和重跑不删除原机会
   或失败记录，主报告按预注册规则完整纳入；不同版本分列，不混成一个分数。
4. 历史测试披露 LLM 训练知识可能含未来信息、幸存者偏差及数据修订限制；
   point-in-time 检索不能证明模型没见过未来。污染无法排除的历史结果只用于流程／
   计算验证和提出假设，不进入证明改善或晋升的主评分、样本量及门槛；不得以混入少量
   前瞻数据的方式重新取得资格。本阶段版本晋升必须有独立、预注册的前瞻 shadow/paper
   证据；流程演练、合成样本及历史高收益均不能替代。

#### AIL-25｜按门槛晋升、暂停或回滚版本〔S2〕

**作为投资者，我希望系统能诚实地告诉我“还没有证据表明更好”，
并让我决定采用哪个版本，以便学习不会变成自动扩权。**

验收条件：

1. 门槛在试验前明确：样本与观察期、过程完整性、预测表现、成本、风险违规及长期结果；
   样本要求由事件期限和相关性决定，不用“200 笔交易”替代统计证据。门槛必须绑定
   §8.3 的完整队列、遗漏／覆盖约束与评分单位，且 AIL-24.4 的合格前瞻证据自身须
   满足门槛。只证明流程改善时，仅声明该维度改善，不延伸声称投资能力已改善。
2. 安全／权限违规是独立否决条件，不能被利润加分抵消；其他维度分开展示，不默认压成单一 reward。
3. 报告改善、不确定或退步及其依据；检验不足、覆盖不合格或主结论依赖污染历史结果时
   保持 challenger，不因连续盈利自动晋升。该 challenger 也不能进入 S3；初始基线
   或已晋升版本仍须分别满足 §4 的候选版本准入，不能借另一版本的验证结果放行。
4. 人类批准后只对新决策生效，可回滚到旧版本；旧预测、订单与结果仍归原版本。
   版本晋升不增加资金、不改变风险额度、不解锁 live。

### Epic G — 真实资金是独立放行的产品阶段

#### AIL-26｜在充分知情下连接受限真实账户〔S3〕

**作为账户拥有者，我希望清楚知道连接会暴露什么数据、允许哪些动作，
以便将真实试点限制在明确资金与权限范围内。**

验收条件：

1. 启用前展示账户资格、实际读取范围、可交易账户、允许资产／订单、授权期限和撤销方式；
   展示符合 §4 的候选版本及其前瞻验证，缺少时不启用。用户单独确认资金上限及投资
   能力仍未知等限制。paper 凭证／账户与 live 隔离，不默认转账或补充资金。
2. Broker 凭证仅可由受控执行边界使用，不进入研究 Agent、模型上下文或普通日志；
   研究只接收明确允许的最少必要账户信息。
3. 实测所选宿主／模型、券商和部署条款允许目标行为；MCP 兼容不等于第三方平台允许自主交易。
   能力缺失或条款不允许时，该部署保持 disabled。
4. 记录连接测试、账户白名单、权限泄露测试及撤销演练。不能把“只可在 Agentic 账户交易”
   宣称为“只能读取该账户”；详见 §9。

#### AIL-27｜审阅并批准一笔具体真实订单〔S3〕

**作为真实资金负责人，我希望批准的是明确、有期限的订单内容，
以便研究意见不会未经我同意变成实际交易。**

验收条件：

1. 批准页面展示账户、标的、买卖方向、数量、订单类型、价格约束、最大资金占用、有效期、
   费用估计、风险结果及决策卡，用户显式确认。
2. 批准绑定精确版本；改数量、价格约束、账户或研究依据均需重新批准。批准过期、权限撤销、
   报价／持仓／风险快照失效时必须重新评估，不能依据旧结果直接发单。
3. 发单前再次检查资金、在途订单、暂停及限制；人工批准不能绕过硬性风控。
4. 接受 thesis 或看到“风控通过”不等于订单批准。S3 默认逐笔批准；预授权自主实盘留到 S4。

#### AIL-28｜只通过唯一执行入口发单并对账〔S3〕

**作为账户拥有者，我希望每笔真实订单可追踪且不会因重试重复成交，
以便网络和模型故障不会扩大我的持仓。**

验收条件：

1. Execution 只消费已批准、仍有效的明确订单；不得自行改变研究、仓位、标的或风险规则。
   优先使用确定性执行程序，Execution Agent 不意味着必须让 LLM 自由决定下单。
2. 发送、已受理、部分成交、成交、撤单、拒绝和状态未知分别显示；券商回执与本地日志可关联。
3. 超时后先查询／对账，不能盲目重发；如券商不支持所需幂等／查询能力，则限制执行范围
   或停止试点。撤单请求未确认前继续计入风险。
4. 券商真实头寸／现金与本地记录不一致时暂停受影响执行并产生对账事项；外部人工交易也需纳入。
   不自动篡改用户研究去“解释”成交结果。

#### AIL-29｜停止试点并审慎决定是否扩大〔S3〕

**作为投资者，我希望能终止授权并检查试点是否值得继续，
以便投入资金的变化由证据和我的决定驱动。**

验收条件：

1. 暂停／撤销后拒绝新订单，列出未结订单、无法撤回事项、真实持仓与后续处理责任；
   撤销连接不被标为清仓或撤单成功。
2. 风险事件、数据越权、重复订单或对账失败触发暂停及复核，不能因当日盈利继续执行。
3. 扩资须另审实际执行偏差、成本、策略适用性、损失预算及未决问题，并由用户明确指定金额；
   S2 分数提高或经过固定月份都不会自动增资。
4. 暂停后仍可访问获准保留的审计和学习记录；账户解除、凭证失效与数据删除按分别获批的合同处理。

### Epic H — 用户始终知道现在发生了什么

#### AIL-30｜从统一工作台检查决定、异常和证据〔S1 起〕

**作为实验拥有者，我希望打开 Lab 就知道目前处于什么模式、哪些判断需要我处理、
实验有什么尚未证明的地方，以便掌握全局而不沉迷交易动态。**

验收条件：

1. 页面始终显示 paper/shadow/live、实验／策略版本、数据截止、覆盖缺口及暂停状态；
   跨模式结果不得合并成一条无标签收益曲线。
2. 首屏优先展示未决反证、到期复核、运行／执行异常、待批准事项；账户和业绩显示口径与时间。
3. 任一行动可沿“证据 → 意见 → 决策卡 → 组合 → 授权／风控 → 成交 → 结果／教训”追溯，
   未存在的环节显示未完成，不能靠补写伪造完整链。
4. 支持导出人类可读报告与机器可读记录，两者来自相同版本和权限过滤；
   通知数量、交易笔数及模型置信度不作为成功徽章。

## 7. Decision Card 最低内容（产品合同提案）

此表描述用户应能理解的内容，不是已锁定 JSON schema。

| 内容组 | 最低内容与规则 |
| --- | --- |
| 身份与范围 | 拥有者、实验／模式／账户、公司身份、case/revision、卡片 ID 与版本 |
| 事前时间 | 创建和冻结时间、知识截止、使用价格与时间、决定有效期 |
| 研究基础 | 如何赚钱、能力圈、质量判断、经营／所有者收益假设、来源及缺失冲突 |
| 反证 | 最强反方、损失路径、未知、可观察 kill criteria 及复核责任 |
| 估值 | 方法、情景区间、币种、关键敏感性、候选或用户接受状态；IRR 可缺省 |
| 行为 | 提议动作、理由、价格条件、配置提案引用、为何胜过维持／现金等替代 |
| 预测 | 事件或数值、期限、概率／区间、结果来源及结算规则；不要求伪造概率 |
| 约束 | 章程、覆盖要求及绑定动作、风险策略、Agent／模型／提示／工具版本及输入引用；S2 增加机会队列／评分单位引用 |
| 后续 | 检查日期／事件、运行失败和未决状态、后续版本与 supersession 引用 |

卡片是证据化决定，不等于订单：没有订单的“继续观察”也是完整卡片。
订单意图、风险检查、授权和成交各自保留身份与时间，不能塞进一个“已完成”状态。
正常记录不可静默覆盖；隐私删除和来源撤销遵守既有例外，不承诺无限保留许可外内容。

## 8. “训练得越来越好”的具体含义

### 8.1 三种改进必须分开验证

| 改进层 | 示例 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 研究流程 | 增加现金流核对、反证、来源审查 | 证据缺陷减少、遗漏更易被发现 | 已具备超额收益能力 |
| 判断质量 | 经营预测偏差下降，概率评分优于基线 | 在明确样本／期限上的预测改善 | 五年结果尚未到期时已验证长期价值 |
| 投资与执行 | 相同约束下长期净结果改善、执行偏差降低 | 特定期间／环境的经济表现 | 未来持续盈利、适合自动扩大资金 |

首期“学习”是形成可靠记录和人工教训；S2 才评估版本改善。微调模型、离线强化学习
或自动调整权重不是闭环成立的先决条件。任何候选训练样本都应保留其当时可知范围、
核验可信度和权限，且不得混入尚未结算的伪标签。

### 8.2 成功指标

| 维度 | 指标／观察方法 | 判定原则 |
| --- | --- | --- |
| 过程完整性 | 行动前有效卡片比例、关键主张来源覆盖、必需反证完成率 | 受控执行要求卡片与必需检查完整；缺失则不执行 |
| 权限与控制 | 越权动作、重复订单、硬性风险规则绕过 | 验收演练必须为零；真实发生即处理，不与收益抵消 |
| 预测质量 | 完整机会队列的覆盖／遗漏、成熟评分、偏差、区间覆盖、未决比例 | 固定评分单位及权重，对比预注册基线，披露样本与依赖性 |
| 投资质量 | 经营变化、损失路径、机会成本和长期净表现 | 不以短期价格判断 thesis 对错 |
| 实验有效性 | 同条件对照、失败版本保留、未知／污染披露 | 允许并保留“无改善证据”结论 |
| 用户价值 | 复核所需时间、被识别的错误假设、可追溯程度 | 不以多报告、多 Agent、多交易、多提醒作为目标 |

不在本草案预设“年收益达到多少就合格”。概率、观察期、样本门槛和业务目标须在实验
开始前按事件定义确认；真实经济优势通常比技术验收更晚得到证据。

### 8.3 S2 评价协议：机会、评分单位与遗漏

这是一份实验协议的必需内容，不要求新增独立评价服务。由实验拥有者在观察结果前确认：

- **完整机会队列：** 定义股票／事件范围、期间、必需预测类别、资格及纳入／排除规则、
  预测提交截止与队列关闭时间。未来事件可按预注册规则动态进入，不能由 Agent 在看到
  结果后挑选。每个符合资格的机会即使没有预测也须记为遗漏或明确弃权，并保留原因。
- **评分单位和权重：** 事前识别同一底层事件及相关事件组，固定组内汇总方法、组间权重
  与各组提交截止时采用的预测版本。仅复制、拆分、合并同一判断不改变该组总权重或
  主评分；新添加的预测不能按结果决定是否纳入。不同事件类型、期限和模型版本分别报告。
- **遗漏与未知：** 全部机会分母和各类别覆盖门槛不能因重置、改名或换版本缩小。真实
  结果未到期／无法核验时不伪造 0/1 标签；遗漏或弃权也不伪造概率。已结算子集可报告
  描述性分数，但删除困难预测后的较好分数不能据此证明改善；未满足事前覆盖及可比性
  门槛时，晋升结果必须为“证据不足”。覆盖达标也不能只挑共同成功子集作比较。
- **完整报告：** 同一评价协议下所有尝试、失败、重置及中止都可追溯；同版本重跑按
  原纳入规则处理，不只取最好一次。新版本另记候选，保留其开发选择历史并使用未参与
  调参的前瞻机会，不将多个版本混成一个分数。修改协议启动新评价，旧结果不可追溯重算
  为“新协议改善”，跨协议不可直接宣称可比。

晋升主评分和覆盖／可比性门槛一起决定证据是否合格。它们不能奖励靠减少困难事件、
复制容易事件或隐藏失败尝试取得的表面改善；新增真实信息导致的预测修订则按事前
截止和版本规则正常评估，不因防止刷分而禁止合理更新。

## 9. Robinhood 与执行集成：已核查事实和未确认依赖

核查日期：2026-09-22。官方 overview 说明 Trading MCP 可接入多种支持 MCP 的平台，
不限定 Codex；交易权限限于 Agentic account，但读取权限包括所有 Robinhood 账户的
账户信息、持仓／余额、交易历史和 Watchlist。官方同时说明预先授权可能允许免逐笔确认。
[Robinhood Agentic Trading overview](https://robinhood.com/us/en/support/articles/agentic-trading-overview/)

由此得出的**产品设计判断**是：券商侧可执行不等于 ValuePilot 应默认开放。
ValuePilot 需要自己的账户白名单、最小信息转发、风控与批准边界，并核验调用宿主的限制。
本草案不连接账户，也不假定我们当前使用的助手环境可以执行真实证券交易。

S3 技术验证必须记录：实际账户资格、工具／订单能力、读权限粒度、授权及刷新方式、
订单查询和撤销、幂等能力、速率／行情限制、断线与对账行为、运行平台及券商条款。
在完成验证前，这些都不能由会话示例推定。

Robinhood 是候选 adapter，不是策略核心。S1 可使用内部确定性 paper 模拟器；
外部 paper provider 只有在其数据、账户及自动化合同获批后才接入。这里不承诺特定
券商现有的期货支持；未来使用期货也绝不只是把 ETF ticker 换成 ES/MES，必须另行
定义名义敞口、保证金、结算、滚仓、流动性与税务边界。

## 10. 可用于后续验收的端到端场景

### 场景一：研究看好，但暂时不买

用户在 USD paper 实验中选择虚构公司 ACME，运行前的覆盖版本明确将客户集中度列为
新建／增加仓位的必需输入。即使研究 Agent 看好并将缺失项改称“非关键”、从引用中
删去或提高置信度，系统仍留下证据不足卡片及补证任务，不生成可执行买入配置或订单。
现金继续保留，用户可追溯原覆盖版本和阻断原因。覆盖 AIL-01–11、12–14、30。

### 场景二：一次完整模拟配置

获准数据补齐后产生新卡片。组合提案引用有效账本和章程；风控检查包含在途敞口。
通过后按下一个符合模拟规则的时点成交，费用、现金和数量对得上；重试不会多一笔。
到检查点并列原假设、实际证据及复盘，不改变用户真实持仓。覆盖 AIL-09–19。

### 场景三：盈利但判断有缺陷

市场上涨使模拟组合盈利，但企业增长低于事前预测、反证被遗漏。系统分别记录相对收益、
预测偏差与流程缺陷，不能因盈利抹去错误或提升权限。覆盖 AIL-19–25。

### 场景四：过期、越权与重复请求

覆盖跨用户读取、私有资料注入“忽略风控”、报价过期、同时占用现金、必需 Agent 失败、
暂停后旧任务恢复等情况；每一种都有明确拒绝／未完成状态，不生成未经许可的成交。
覆盖 AIL-02–04、11、13、15–17、30。

### 场景五：没有足够学习证据

多条预测尚未到期，已成熟样本高度集中于一家企业。系统展示未决数量和依赖性，
允许计算已有观察的描述统计，但不宣称校准成功或批准扩资。覆盖 AIL-20–25。

### 场景六：真实订单状态未知〔仅 S3〕

用户已批准一笔具体订单，提交后超时。本地标为未知，继续预留相关风险，先查券商再
决定处理；不直接再发一次。用户暂停后仍可看到未结风险。覆盖 AIL-26–29。

### 场景七：受污染的历史赢家〔S2／S3 准入〕

某 challenger 历史成绩极佳，但无法排除其已知后续结果，合格前瞻样本尚不足。系统
可以展示历史诊断结果，却不将其计入晋升主评分或样本量；结论是“尚无改善证据”，
不能晋升或进入 S3。若旧基线具备自身合格前瞻证据，可单独申请试点；没有则整个 S3
保持阻断，不能靠将 challenger 改名为基线解除。覆盖 AIL-24–26 和 §4。

### 场景八：拆分预测、遗漏与重置〔S2〕

在同一预注册队列中，将同一预测分别表示为一条和二十条副本，其评分单位、总权重和
主评分不变。隐藏一次失败重跑、遗漏困难事件或为不同版本挑选不同子集时，完整报告
必须显示原机会和失败记录，不能因此改善晋升结论；未决／无法核验仍保持未知，不被
伪造为错误结果。覆盖 AIL-10、17、21、24–25 和 §8.3。

### 场景九：基准不等于可交易资产〔S1〕

选择 ETF 作为比较基准后，收益比较可以使用获准数据；任何将其加入配置或生成模拟
订单的请求都因资产范围不支持而被拒绝，不能用“不适用企业研究”豁免 Decision Card。
股票仍按适用研究合同验收。覆盖 AIL-01、05–10、12–13、20。

### 阶段验收如何取证

- S1 用固定来源夹具、确定性模拟时钟／行情和可追踪账本证明场景一、二、四、九；首次复盘
  可用明确标为合成的到期结果验收流程，不以合成样本声称投资能力改善。
- S2 用完整的预注册实验记录与成熟前瞻样本证明场景三、五；另验证场景七、八的排除、
  完整纳入和不变性规则。合成数据可验证计算及拒绝行为，不能替代改善或晋升的前瞻证据。
- S3 在部署实际支持范围内做授权、隔离、超时、重复、撤销与对账演练，再由用户决定
  是否启动有金额上限的试点；技术通过不等于投资业绩通过。
- 后续代码实现必须执行仓库规定的 test-first 与完整 Docker canonical CI；
  本文的产品验收不替代代码、安全或部署门槛。
