## 1. 唯一交付目标

用户在现有应用内，查看一家公司的可信财务及证据，解释生意和风险，
记录自己的估值依据或不能估值的原因，明确作出研究决定，并在下次打开时找回原判断。

对应 AGENTS 六项工作：理解生意、重构经济性、评估价格、主动否证和保存复查依据。
首批以人工判断为核心，不承诺自动 Owner Earnings、自动估值或自动识别 thesis delta。

## 2. 边界：一个用户、一家公司、一个现有研究页面

- 从已保留的 8 家中选择一家非金融、USD、已有证据最可用的公司。
  先做只读盘点，再在任务记录锁定 ticker/CIK/listing、截止日、预期期间和指标；
  不在测试失败后换公司或缩减分母。选择依据是数据和范围，不是投资推荐。
- 展示最多十个已完成 FY 的已有历史；缺年明确标出；最新已保留季度可查看，不新增全季度研究系统。
- 复用 `/research/cases/[id]`，不用新建 Research 平台、独立笔记系统或仪表盘。
- 复用现有 thesis、variant view、assumptions、risks、evidence、valuation、revision 和决策服务。
- 普通研究者完成流程不能依赖 SQL/CLI；一次性、明确授权的操作员数据准备可以用现有工具。
- 首批不新增数据库表、研究状态、事实存储或投资评分。若确需改变 schema/语义，先说明不可复用原因，
  返回用户审查；不能藏进实现，也不能利用 JSON 绕开需要批准的存储契约。

不做：新 DCF、自动盈利调整/增量 ROIC、AI、多公司扩抓、完整审查后台、实时行情、
新报价商、通知渠道、量化/期权/交易、账户注销、全站导航重构、通用迁移/导入平台。
EOD 未启用时保留现有 unavailable，不能伪造 MOS；这不阻止阅读企业和保存人工判断。

## 3. 三个顺序交付的小改动

### S1 — 让已有真实财务在当前应用可读

**目标：** 不只在验收库有记录，目标公司的可信历史能由当前产品正常读取。

复用 SEC retention、identity、parse、mapping、publication 和现有 source policy。
先盘点文件/版本/空间和发布缺口，区别“已有未发布”“缺 artifact”“缺 mapping 支持”，再补最小缺口。
现有 schema 的安全复用路径尚需实证，计划不假设已有通用跨库导入命令。

只为选定公司/期间准备数据；优先复用内容寻址文件，不重复下载全部档案、复制整库或 raw facts。
目标库、存储路径、磁盘预算及任何新增网络拉取先获用户确认；不得修改保留验收证据或生产库。
用正常授权服务建立当前 lineage；保留 source 时间，新建关系记录真实创建/knowledge 时间，不回填伪造历史。
如现有工具无法复用，先报告最小差距和资源成本，不自行建设导入框架。

最小财务内容：收入、净利润、经营现金流、资本开支、现金、债务、股数；仅使用批准的 canonical 定义。
现金口径、债务组成、股数种类分开标注，不能为凑齐列表强行相加或混用。
SBC、营运资本、收购等重大事项至少有可查看的原始证据和人工研究记录入口；不是伪造自动计算值。

**验收：**

- 选定期间的 canonical 数据由当前应用的 `metric_facts` 正常返回；每个数字可定位授权证据。
- 截止日最近三个连续已完成 FY 的上述核心财务可核对、口径明确；其余十年窗口的实际覆盖/缺口逐年可见。
  如暂不能获得该最低分析基础，记录阻塞，不以“所有值都 unavailable”判本步骤成功。
- 展示与引用区分实际、预测、调整值、来源、币种和期间；不可比序列不计算增长。
- 同输入重复执行不会追加语义重复事实或破坏其他期间/来源的 current；不超出锁定且获授权的公司/期间。

### S2 — 在原研究页面读懂财务，不被容量和原始 key 阻挡

**目标：** 用户能看历史、查来源、理解缺口，不需导出到另一套工具整理。

先按现有 PRD §H.10 提交窄范围查询契约调整供审查：从整公司截断改为完整比较单元的有界读取。
契约获准后才改代码；不简单提高 250 或去掉 fail-closed。
分页是展示边界，不能是冲突检查边界：同槽位全部候选、必要的递归 lineage 和适用权限/时点仍须检查。
单元无法完整验证时仅给出该单元的明确 unavailable，不从部分前缀选一个数字。
跨页使用同一有证据支持的读取边界；若刷新后失效，明确刷新/拒绝，不伪装为完整历史快照。

在原页添加简洁年度表和人类可读标签；期间为列、核心指标为行。
以现有 mapping 提供单位/定义；多来源分开展示及说明差异，复用共享 reconciliation，不新增自动优先源。
可展开证据、其他指标和缺失原因；不做图表框架、报表配置器或一键强制解决冲突。

**验收：**

- >250 条候选和 >60 条可展示事实的夹具中，安全单元仍可遍历；没有静默遗漏或重复。
- 页外同槽位冲突、派生依赖冲突、失权及晚于 cutoff 的候选仍按契约阻止/排除；不能利用筛选绕过检查。
- 目标公司的十年窗口、数据空缺、源角色和原始证据可直接阅读；缺失不是零。
- 不修改 facts、不改变 current 槽位、不创建另一个财务 truth；已有其他消费端保持行为一致。

### S3 — 引导用户形成自己的判断，并复用现有保存流程

**目标：** 从“空文本框”变成有用的问题提示，但不建立新的状态机或自动结论系统。

用现有字段的标签、帮助文字和明确的用户主动插入提示，覆盖：

1. 我是否理解它怎样赚钱？优势来自哪里，什么仍不理解？
2. 历史现金创造与债务说明什么？资本配置和再投资是否可信？
3. 我为什么可能错？什么事实会使我放弃原判断？
4. 我的估值区间依据是什么？关键盈利/投入/增长假设是什么；或为什么目前无法负责地估值？
5. 我决定 watch / own / pass 的理由是什么？何时复查？

thesis/variant view 承载研究论述，assumptions/risks 仍使用现有内容格式，证据仍显式引用。
允许人工描述维护性投资、SBC 等调整和估值推导，但本批不计算、不生成 canonical 派生事实。
不把占位提示保存为用户答案，不覆盖旧内容，不强制为了填表编造护城河、数字或结论。

沿用现有 USD low/base/high、不能估值原因、expected head、Save/Decide/Review 和原子发布。
清楚提示：包含估值的服务器保存按既有规则更新本人估值投影，不新增秘密的“已保存未发布”分支。
不启用 system valuation，不要求修改行业方法政策才能阅读原始 canonical actuals 或保存人工判断。

**验收：**

- 用户能从股票入口打开案例、核对证据、写出商业判断、反方、至少一条可否证条件和估值依据，完成显式决定。
- 验证“人工区间”和“不能估值”两条路径；后者合法，但不能替代 S1 的真实财务验收。
- 刷新后内容和证据可找回；修改产生新 revision，旧决定可读；过期 head 返回既有 409，不覆盖。
- 旧案例读写兼容；只有现有决定规则要求的字段阻止保存，不创建新的资格评分或审批流程。
- 使用既有下一次复查日期和历史入口手动复查；自动经营事件监控属于后续，不计为已完成。

| 小步 | 主要复用/可能修改 | 不要扩展到 |

新发现的非阻塞问题进入 BACKLOG；缺少权限、重大语义变化、数据风险或资源超预算时停止请求决定。

## 5. 最终验收与停止线

用户亲自在浏览器完成一次：打开锁定公司 → 阅读历史 → 查看现金流/债务证据 →
写业务判断、反方和否证条件 → 记录人工估值依据或不能估值原因 → 显式决定 → 刷新找回 → 手动追加复查。
除了首次操作员准备和用户登录，流程不依赖 agent 代填、SQL、CLI 或表外整理。
记录使用的 commit、目标环境、公司/截止日、证据引用、实际缺口及失败步骤，不承诺投资回报。

每个实现 closing gate 按 AGENTS 原样执行全部命令；先确认目标开发环境及迁移授权，不测试/迁移保留验收库或生产库：

```sh
docker compose up -d --build
docker compose exec -T api alembic upgrade head
docker compose exec -T api pytest -q
docker compose exec -T web sh -lc 'node --test lib/*.test.js'
docker compose exec -T web npm run lint
docker compose exec -T web sh -lc 'NODE_ENV=production npm run build'
```

另检查 `git diff --check`。聚焦测试不能替代全套；CI 不能替代真实用户操作。
