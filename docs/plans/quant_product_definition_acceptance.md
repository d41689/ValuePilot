**Status:** 正式验收依据(companion to `quant_trading_system_architecture_plan.md` v10)。

## 1. 产品形态:两段式,两种形态

### Phase 1 的产品 = 研究裁决机(交付物是报告,不是界面)

它回答一个问题:**"这里有没有值得建交易系统的 edge?"** PO 摸得到的产出物:

1. **1-R0 数据审计报告**(markdown)——数据可得性矩阵、年数 × 每期宽度 × 覆盖率、按 H1/H2/H3 的功效分析、数据采购决定。
2. **每周 VL 归档任务**——scheduler 里可见,`pdf_documents` 周增量可查,漏周告警。
3. **1-R3 因子分析报告**——每个因子的 decile 收益图、IC、换手;附外部锚对照(见验收表)。
4. **1-R4 研究裁决书**——H1/H2/H3 各自的净 α、t_HAC、DSR、BH 结论与 PASS/FAIL 徽章;
   闸门判定(Phase 2 解锁与否);预注册留痕(`backtest_runs` 的 `trial_group_id` 时间戳)。

**看不见的部分**(1-R1 PIT 读取引擎、1-R2 计算注册表)没有界面,验收靠陷阱测试(见 §2)。

### Phase 2 的产品 = 个人量化基金驾驶舱(挂在现有 ValuePilot React 前端)

每周操作循环:**开盘前打开 dashboard → 看 regime/持仓/漂移 → 审查系统生成的建议交易篮子
(含 spec-ID 税务批次选择)→ 人工点批准 → IBKR 执行 → 自动对账。**

Dashboard 常驻面板:组合净值 vs 基准、regime 状态(信封敞口)、总敞口分解(核心/sleeve)、
kill-switch 状态(漂移 σ、回撤 vs 限额)、待批准篮子、周归档与漂移月报状态条。
人工批准闸门是硬性的:没有"全自动下单"模式。

## 2. Phase 1 验收清单(PO 亲自执行)

| # | 交付物 | PO 验收动作 | 通过标准 |
|---|---|---|---|
| P1-A | 1-R0 审计报告 | 通读 | 有具体数字与明确的 GO/NO-GO 功效结论,无"待定" |
| P1-B | 周归档任务 | 查 `pdf_documents` 周增量;**故意停一次任务** | 连续 4 周无缺口;停跑一次告警必须响 |
| P1-C | PIT 读取(1-R1) | **陷阱测试**:选一个后来被修正过的历史值,要求读 T 日值 | 返回"当时的值",不是"现在的值";`is_current` 未被用于历史读取 |
| P1-D | 计算注册表(1-R2) | 要求回测消费一个未注册的 calculated 指标 | **fail-closed**:报错拒绝,而非静默读存量行 |
| P1-E | 1-R3 因子报告 | 对照**外部锚** | 我们的动量因子月收益与 Ken French UMD 相关性 > 0.9;明显偏离必须有书面解释 |
| P1-F | 1-R4 裁决书 ① | 查预注册时间戳 | `trial_group_id` 全部行的记录时间**早于** holdout 解锁时间 |
| P1-G | 1-R4 裁决书 ② | 对照 v10 §14 数字门槛 | t_HAC ≥ 3(单侧、α>0)、DSR P(skill) ≥ 0.95、BH q=0.05、净 α ≥ 2%/yr、investability 全过 |
| P1-H | 1-R4 裁决书 ③ | **换环境复跑**(重建容器再跑一遍) | 所有统计量逐位一致(固定种子保证);不一致 = 验收失败 |

**Phase 1 整体通过 =** P1-A…H 全过,且闸门判定符合 v10 kill rule
(H1/H3 至少一个 PASS → Phase 2 解锁;全 FAIL → 触发预注册 fallback,Phase 2 不开工)。

**2026-07-21 验收状态:** P1-A 的可重复报告已交付并给出明确
`NO_GO`; 这不等于 Phase 1 通过。P1-B 尚未通过(仅 2 个非连续归档周,
且 Value Line 自动获取未获授权),P1-C…P1-H 按门禁保持关闭。

## 3. Phase 2 验收清单(先假钱、再演习、后真钱)

| # | 阶段 | PO 验收动作 | 通过标准 |
|---|---|---|---|
| P2-A | Paper mode(4–8 周,`mode='paper'`) | 对比 paper 组合与回测引擎同期输出 | **逐笔一致**(研究-实盘同源的活体检验);差异必须归因到数据时点差 |
| P2-B | Kill-switch 消防演习 | 人为注入超阈值回撤/漂移数据 | 系统冻结新单 + 降到 regime 下限;**重启需人工复核**,不是自动恢复 |
| P2-C | 对账 | IBKR 成交回报 vs `broker_holdings`/`tax_lots` | 连续 4 周零差异;spec-ID 批次选择与税务意图一致 |
| P2-D | 篮子闸门 | 审一次真实再平衡篮子 | 每笔交易可追溯到规则(进入前 20%/跌出后 40%/信封调整);无解释不了的交易 |
| P2-E | 小资金上线 | sleeve 预算内实盘 ≥ 4 周 | 滑点/成本在回测模型假设范围内(月报对照) |

**上线后的常设验收:** 每月一份 live-vs-backtest 漂移报告;PO 每月读一次,连续两月超界 →
按 2-M5 decommission 流程处理。H2(VL 真实排名残差)按预注册日期评估,期间只积累不评判。

## 4. 三条 PO 须知(诚实条款)

1. **最早摸到手的产品是 Phase 1 的报告,不是交易界面。** H1/H3 全败则驾驶舱永远不会建——
   这是设计意图,不是延期。
2. **时间线最大不确定项是 1-R0 的数据采购**(商品数据源到位才能跑 H1);
   最确定的义务是**每周归档立刻开始且不许断**(H2 原料不可回补)。
3. **P1-F(预注册早于解锁)是全系统防自欺的最后一道锁**——这一条 PO 必须亲自查时间戳,
   不得委托给实现者。
